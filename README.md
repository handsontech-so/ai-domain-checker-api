# AI Domain Checker API

A FastAPI-based API for evaluating domain names with an LLM-assisted risk assessment workflow. The service sends a structured prompt to Ollama and returns a JSON payload describing the domain’s likely risk level, a numeric score, a short summary message, and supporting reasons.

## Overview

This project is a lightweight backend service for domain reputation analysis. It is useful for applications that want to flag potentially suspicious, phishing-like, or brand-impersonating domains before they are trusted or displayed to users.

The current implementation exposes one main analysis endpoint and a health check route, and it is designed to be easy to run locally with uv and deploy behind a web server or container platform.

## Key Features

- FastAPI-based REST API
- Domain analysis endpoint powered by Ollama
- JSON response structure for downstream integrations
- Built-in rate limiting with SlowAPI
- CORS support for browser-based clients
- Environment-based configuration using python-dotenv

## How It Works

1. A client sends a request to the analysis endpoint with a domain value.
2. The API builds a prompt for the LLM.
3. The Ollama-backed service generates a response.
4. The API parses and returns the JSON payload to the client.

## Prerequisites

Before running the project, ensure that you have:

- Python 3.12 or newer installed
- uv installed and available on your PATH
- An Ollama-compatible API key configured in your environment
- Access to the Ollama service or provider used by the project

## Installation

This project uses uv for dependency management and execution.

Clone the repository and install dependencies:

```bash
git clone <repository-url>
cd ai-domain-checker-api
uv sync
```

If uv is not installed yet, install it first:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

## Configuration

Create a local environment file from the example:

```bash
cp .env.example .env
```

Then set your environment variables in the .env file:

```env
OLLAMA_API_KEY=your-api-key
```

The application loads configuration from the environment at startup.

## Running the Application

Start the API locally with:

```bash
uv run uvicorn main:app --reload --host 0.0.0.0 --port 8000
```

Once running, the service will be available at:

- http://127.0.0.1:8000
- http://127.0.0.1:8000/docs for the Swagger UI

## API Reference

### Health Check

GET /

Example response:

```json
{
  "health": "ok",
  "datetime": "2026-08-09T00:00:00",
  "status": "running.....",
  "message": "Welcome to the FastAPI application! deployed on digital ocean via ci/cd github actions."
}
```

### Analyze Domain

POST /api/v1/domains/analyze

Request body:

```json
{
  "domain": "https://example.com"
}
```

Example response:

```json
{
  "risk": "low",
  "score": 10,
  "message": "This domain appears to be a typical, low-risk website.",
  "reasons": [
    "The structure looks standard and legitimate.",
    "No obvious brand impersonation indicators were detected."
  ]
}
```

### Example cURL Request

```bash
curl -X POST "http://127.0.0.1:8000/api/v1/domains/analyze" \
  -H "Content-Type: application/json" \
  -d '{"domain": "https://example.com"}'
```

## Request and Response Notes

- The request payload uses a domain field and expects a valid URL-like value.
- The response is expected to be valid JSON generated by the LLM and parsed by the application.
- The API currently applies a default rate limit of 10 requests per minute.
- If the upstream Ollama service or model fails, the request will return an internal error response rather than crash the server.

## Configuration and Behavior Details

- The API is mounted from the main entrypoint in main.py.
- The router is defined in app/api/routes.py and uses the prefix /api/v1/domains.
- The service layer for LLM interaction lives in app/services/ollama_service.py.
- The schema for the request payload is defined in app/schemas/domain.py.
- The base abstraction for LLM providers is defined in app/core/base_llm.py.

## Deployment Notes

This project is suitable for deployment on platforms such as DigitalOcean, Render, Railway, or other container-based hosting services.

Recommended deployment checklist:

1. Set the environment variable for Ollama authentication.
2. Ensure the application is running with Python 3.12+.
3. Configure secrets management instead of hardcoding API keys.
4. Enable logging, monitoring, and request tracing for production use.
5. Review rate limiting and input validation for public-facing deployments.

## Troubleshooting

- If the server fails to start, confirm that dependencies were installed with uv sync.
- If analysis requests fail, verify that the OLLAMA_API_KEY environment variable is set correctly.
- If the response is empty or invalid, check the Ollama connection and model availability.
- If you receive validation errors, ensure the domain value is provided in a valid URL-like format.

## Limitations

- The quality of the analysis depends on the model and prompt configuration.
- The current implementation uses a single prompt and a single provider integration.
- Production deployments should add stronger validation, retries, observability, and fallback handling.
